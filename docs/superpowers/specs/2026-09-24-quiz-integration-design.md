# Дизайн: голосовая викторина в навыке «Скажи домашку» (интеграция quiz-library)

Дата: 2026-09-24
Статус: черновик на утверждение
Проект: [alice-homework] (навык, эта интеграция)
Зависит от: [quiz-library](https://github.com/freeuser3/quiz-library) и
[дизайн викторины](2026-09-24-alice-quiz-design.md) (спека проекта в GeoRag).
Продолжает: [дизайн навыка](2026-09-17-alice-homework-design.md).

## 1. Цель

Добавить в навык «Скажи домашку» голосовую викторину: по команде типа
«спроси по географии» навык берёт из кэша домашнего задания запись по
предмету, парсит номер параграфа («параграф 6»), генерирует **один** вопрос
через quiz-library (DS Lab, gpt-4.1-nano) и озвучивает его. Сценарий v1:
один вопрос за триггер, без проверки ответа.

## 2. Вне области (YAGNI для v1)

- Проверка/оценка ответа ребёнка (в API quiz-library заложено место).
- Опрос из нескольких вопросов за сеанс (FSM).
- Мультиюзерные сессии и персональные кэши квиза.
- Хранение выжимок в git репо навыка (`digests/` и `subjects.json` —
  приватные данные, gitignored).
- Изменения в quiz-library: она уже реализована и опубликована; навык только
  подключает её как зависимость.

## 3. Решения, согласованные с пользователем

1. **Тайминг ответа**: пробовать ответить сразу (await генерации с бюджетом
   3.5 с); не уложились — «Секунду, придумываю вопрос…» + фоновая генерация,
   вопрос отдаётся по «дальше». Запущенный запрос **не отменяется** (паттерн
   `asyncio.wait` с `FIRST_COMPLETED`), чтобы fallback не делал второй вызов.
2. **Конфигурация квиза опциональна**: при отсутствии `llm`-секции или ключа
   навык работает как раньше, а quiz-команды отвечают «Викторина не
   настроена». Существующие деплои не ломаются.

## 4. Архитектура (подход A — тонкая обвязка, no FSM)

Одна asyncio-процедура, состояние квиза — отдельный слабый слот
`QuizSlot` (аналогично тому, как `HomeworkCache` сейчас служит хранилищем
отложенного ответа). Новый механизм не вводится.

```
Алиса «спроси по географии»
        │ quiz_router (contains «спроси»/«проверь» + предмет)
        ▼
cache.entries → find_entry(предмет) → parse_paragraph(entry.content)
        │
        ▼  нет параграфа → «Не нашла параграф…»
quiz_service.question_for(entry)   (quiz-library, async, прямого вызова)
        │  ≤3.5 с → повторить цель вопроса; >3.5 с → QuizSlot.pending_task
        ▼
«дальше» (more_router): QuizSlot.question есть → вопрос (слот очищается);
        pending_task без вопроса → «Ещё чуть-чуть…»; иначе — домашка как раньше
```

Почему слот отдельный, а не поле в `HomeworkCache`: «дальше» должно приоритетно
отдавать вопрос квиза, но не затирать домашку. Отдельный слот инжектится в
Dispatcher через `workflow_data` — тем же способом, что `cache` и `worker`.

## 5. Конфигурация (опциональный блок)

`config.json`:
```json
{
  "sgo": {…},
  "skill_id": "…",
  "subjects_path": "subjects.json",
  "llm": {
    "base_url": "https://api.dslab.tech/v1",
    "api_key": "sk-…",
    "model": "gpt-4.1-nano",
    "timeout": 20
  }
}
```

| Поле | Env | Дефолт |
|------|-----|--------|
| `subjects_path` | `SUBJECTS_PATH` | `subjects.json` |
| `llm.base_url` | `LLM_BASE_URL` | `https://api.dslab.tech/v1` |
| `llm.api_key` | `LLM_API_KEY` | — (пусто → квиз «не настроен») |
| `llm.model` | `LLM_MODEL` | `gpt-4.1-nano` (по research-отчёту quiz-library) |
| `llm.timeout` | `LLM_TIMEOUT` | `20` |

Валидация: SGO-креды и `skill_id` по-прежнему обязательны (`ValueError`).
LLM-блок **не** валидируется при старте; `subjects_path` проверяется только при
первом quiz-запросе (файла нет → «Викторина не настроена»). `LLMClient` из
quiz-library создаётся в `create_app` только если `api_key` задана, и закрывается
в `@dp.shutdown()`.

## 6. Поток в quiz-хендлере

1. Разбор команды: слово предмета, case-insensitive, ищется среди ключей
   `subjects.json` («спроси по географии» → «География»). Слова предмета нет —
   берём первую предметную запись из `cache.entries`, если она одна; иначе —
   подсказка «По какому предмету спросить?…».
2. Записи предмета в `cache.entries` нет → «Сегодня по географии ничего не задано».
3. Квиз не настроен (нет ключа/subjects.json/выжимок) → «Викторина не настроена».
4. `parse_paragraph(entry.content, paragraph_patterns)` вернул None →
   «Не нашла параграф в домашнем задании» (плюс подсказка).
5. Есть готовый вопрос в `QuizSlot` для (предмет, параграф) → озвучить сразу.
6. Иначе: запустить `svc.question_for(entry)` как task;
   `done, _ = await asyncio.wait({task}, timeout=3.5)`:
   - `task` in `done` → результат (вопрос или None) → озвучить вопрос или
     «Не получилось придумать вопрос»;
   - не уложились → `QuizSlot.pending_task = task`,
     ответ «Секунду, придумываю вопрос… Скажи «дальше».».

Ошибки из `task.result()` (возбуждаются только после `done`): `LLMError`
квиз-обёртка превращает в None-ответ (фраза «Не получилось…»); прочие —
через существующий `@dp.errors()`.

## 7. `more_router` («дальше») — приоритет квиза

Новый порядок в `handle_more`:
1. `QuizSlot.question` не None → вернуть вопрос, **очистить слот** (однократный
   повтор по «дальше»).
2. `QuizSlot.pending_task` есть без вопроса → «Ещё чуть-чуть, придумываю…» =
   переиспользованный PREMATURE_QUIZ.
3. Иначе прежнее поведение: `cache.get().text` или `HINT_TEXT`.

## 8. Зависимость

`requirements.txt`: `quiz-library @ git+https://github.com/freeuser3/quiz-library.git`.
`HomeworkEntry` (предмет, текст задания) берётся из `quiz_library.model`; SGO-записи
конвертируются в него при записи в кэш.

## 9. Ошибки

- Нет записи предмета / нет параграфа / не настроено → вежливые фразы
  (см. §6), без исключений.
- Вопрос не сгенерирован (LLM вернул None / ошибка / таймаут при «дальше») →
  «Не получилось придумать вопрос. Попробуй ещё раз».
- Нештатные исключения → существующий `@dp.errors()` и `dp.timeout()`.

## 10. Тестирование

Паттерны репо: прямые вызовы хендлеров с MagicMock'ами; в
`test_skill.py` — Dispatcher-интеграция через `_free_app`. quiz-library
**мокается** (FakeQuizService / установка `svc.question_for` в MagicMock
AsyncMock), реальные выжимки в тесты навыка не попадают (приватные данные;
загрузка покрыта в репо quiz-library).

- `test_quiz_handlers.py`:
  - триггер-фразы («спроси по географии», «проверь по географии», без предмета);
  - кэш без записи предмета → «ничего не задано»;
  - запись без параграфа → «Не нашла параграф…»;
  - быстрый ответ (fake ≤3.5 с) → вопрос сразу, слот пуст;
  - медленный ответ (fake >3.5 с) → premature, слот с pending_task;
  - «дальше» после premature → вопрос, слот очищен; повторное «дальше» → домашка;
  - квиз не настроен → «Викторина не настроена»;
  - LLM-ошибка → «Не получилось…».
- `test_quiz_state.py`: слот хранит/очищает questions и pending_task.
- Обновления существующих: `test_cache.py`/`test_sgo.py` (entries в
  `HomeworkResult`), `test_config.py` (llm-секция, env-оверрайды,
  опциональность), `test_handlers.py` (приоритет слота в `handle_more`),
  `test_skill.py` (инжекция QuizSlot и фабрики).

## 11. Деплой

- `digests/` (выжимки) и `subjects.json` — приватные на сервере, в .gitignore.
- `LLM_API_KEY` — env; в репо ключа нет (`config.example.json` — без ключа).
- Библиотека ставится `git+https` из GitHub; новых сервисов нет.
- Публикация репо навыка на GitHub / режим работы — по решению пользователя.

## 12. Границы

- Навык не знает про формат выжимок и параграфы: всё через quiz-library.
- Гибик quiz не влияет на домашку: слои независимы, «дальше» лишь
  перенаправляет приоритет.
- Изменения quiz-library в этой итерации не требуются.
